# Storybook API mocks

- Mock the public API module import, never the page or state hook.
- `app-api/*` and `admin-api/*` mirror public API domains and satisfy their exported API interfaces. Import production API types with `import type` only.
- `.storybook/main.ts` aliases those imports before the general `@` alias. An unmocked production API module must fail the Storybook build.
- `runtime.ts` resets fixture data and method overrides per story. Queries return cloned values; state edits must not mutate stored fixtures.
- `apiMock` story parameters choose ready/empty/error/loading responses, delay, and fixture overrides.
- Use actual page components for page stories. Existing primitive/form stories may exercise the same production UI with props, but never duplicate their markup.
- Mock data is illustrative, not a second implementation of production course/enrollment rules. Keep payment, auth and upload effects local; never invoke real provider endpoints.
- Auth actions currently use hard navigation after success, so the auth-client mock returns an explanatory error for login/logout. Choose authenticated/anonymous previews with `apiMock.data.appUser/adminUser`. Password changes are a local success.
- The media API explicitly rejects upload attempts; provide ImageAsset fixtures for uploaded-image states. The payment widget mock renders nothing and rejects opening a payment window. Checkout quote/prepare/confirm, enrollment progress and community writes are in-memory previews on the story's `MockData`.
